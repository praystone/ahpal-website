🎯 核心教訓：為什麼人家都沒陣痛？

❌ AHPAL (初期)
  • 手動改 6 個檔案，容易遺漏
  • 依賴 main.py 的判斷邏輯
  • 批次腳本是複製貼上改造
  • 使用 Interactive 排程 (卡 PIN)
  • 每次新增分類都是「手工藝」
✅ AHPAL (標準化後)
  • 10 步驟標準化 SOP
  • 直接呼叫 article_generator
  • 批次腳本 v2.0 範本
  • 使用 SYSTEM 帳戶 (無 PIN)
  • 標準化流程，一次到位
📌 結論

「人家都沒陣痛」的關鍵在於：他們的系統從一開始就設計對了。
標準化 SOP 讓每次新增分類都是「複製貼上」，而不是「從頭摸索」。

❌ 錯誤 12：未標準化導致多次陣痛

📌 錯誤現象
# 新增「🌳 動植物生態」分類時經歷的陣痛： 1. 建立資料夾 → ✅ 2. 更新 config.py → ✅ 3. 更新 main.py → ✅ 4. 更新 html_builder.py → ✅ 5. 更新 ahpal-master.ps1 → ✅ 6. 更新 check-all.ps1 → ✅ 7. 更新 preflight-check.ps1 → ✅ 8. 建立批次腳本 → ❌ 複製貼上後遺留註解 9. 建立排程 → ❌ 使用 Interactive (卡 PIN) 10. 執行生成 → ❌ main.py 判斷錯誤 (0 篇生成)
🔴 根因分析
  • 沒有標準化作業流程 — 每次都要從頭摸索
  • 批次腳本手動改造 — 複製貼上後遺留問題
  • 依賴 main.py 的缺陷邏輯 — 而不是直接呼叫 article_generator
  • 排程帳戶錯誤 — 使用 Interactive 而非 ServiceAccount
✅ 解決方法
# 標準化 SOP (10 步驟) 1. 建立目錄 2. 更新 config.py 3. 更新 main.py 4. 更新 html_builder.py 5. 更新 ahpal-master.ps1 6. 更新 check-all.ps1 7. 更新 preflight-check.ps1 8. 建立批次腳本 (基於 v2.0 範本) 9. 建立排程 (使用 SYSTEM 帳戶) 10. 驗證 # 🆕 核心原則： # 1. 永遠不依賴 main.py 的判斷邏輯 # 2. 永遠使用 SYSTEM 帳戶排程 # 3. 永遠先掃描目錄
📜 董事長死命令總覽 (10 條)
#死命令說明
1文章變更後強制檢查與推送規範preflight-check.ps1
2文章檔名強制使用英文嚴禁中文檔名
3信箱嚴禁明文外漏董事長信箱嚴格保密
4CSS 靜態資產保護main.css 禁止自動覆蓋
5文章清單集中管理master-articles.json
6文章新增唯一入口pending-articles.json
7首頁完整性create_default_index()
8禁止擅自精簡或改寫既有功能修復前備份、修復後對比
9嚴禁稱呼董事長為「神」禁用一切造神式稱呼
10🆕 新增分類須遵循標準化 SOP依 10 步驟標準流程
⚠️ 此 10 條死命令已錄入紅皮書，作為永久性強制規範。

📋 新增分類標準化 SOP (10 步驟)

  1. 建立目錄 mkdir C:\Users\User\ahpal-static\新分類名稱
  2. 更新 config.py 新增 CATEGORIES 與 CATEGORY_EMOJI_MAP
  3. 更新 main.py 新增 CATEGORY_DIR_MAP 與 CATEGORY_EMOJI_MAP
  4. 更新 html_builder.py 新增 CATEGORY_EMOJI_MAP
  5. 更新 ahpal-master.ps1 新增 $categories 哈希表
  6. 更新 check-all.ps1 新增 $CategoryDirs 與 $CategoryPages
  7. 更新 preflight-check.ps1 新增 $ArticleDirs 與 $Categories
  8. 建立批次腳本 基於 auto-nature-batch.ps1 v2.0 改造
  9. 建立排程 使用 SYSTEM 帳戶 (ServiceAccount)
  10. 驗證 執行 check-all.ps1 -Report

🛑 最終警告

⚰️

這 48 小時的教訓，是用血淚換來的。
