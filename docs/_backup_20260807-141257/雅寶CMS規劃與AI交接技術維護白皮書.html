1. 執行摘要

本白皮書旨在確立 雅寶 CMS（AHPAL Content Management System） 的戰略定位、技術架構與 AI 交接規範，作為 AHPAL.COM 從「指令列自動化」邁向「視覺化數據驅動」的正式文件。

🎯 核心目標
  • 視覺化管理：將 254+ 篇文章、23+ 款遊戲、影音管線、API 配額全數視覺化
  • 數據驅動決策：即時監控品質分數（平均 97 分）、字數、SEO 結構
  • 一鍵指揮：將 PowerShell 管線（`ahpal-master.ps1`）轉化為直覺按鈕
  • AI 交接標準化：確立 LLM 協作（DeepSeek/Gemini/ChatGPT）的技術規範
面向現狀CMS 目標
操作介面PowerShell 指令列Web 視覺化面板
數據呈現日誌檔案即時儀表板
文章管理手動編輯 keywords_list面板篩選/批次操作
部署流程手動執行腳本一鍵觸發
AI 協作臨時指令標準化 API 調用

📌 設計原則
  • 靜態優先：無需額外資料庫，直接讀取現有 JSON
  • 本地安全：API Key（`.env`）絕不進入前端
  • 增量更新：僅更新變更內容，提升效能
  • 品牌一致性：延續 AHPAL 深海藍 + 金色視覺

4. 數據整合與狀態管理

4.1 核心數據檔案

檔案內容更新時機
article-manifest.json每篇文章的 MD5 哈希、品質分數、生成時間、字數每次文章生成後
build-state.json增量構建狀態、檔案變更清單每次生成/部署後
sitemap.xml全站 URL 清單（SEO 核心）每次文章生成後
categories.html全部分類頁面每次文章生成後

4.2 文章品質分數計算標準

指標標準權重
字數≥ 4,500 字25%
H2 標題≥ 3 個20%
H3 標題≥ 2 個15%
對比表格≥ 1 個20%
FAQ 區塊≥ 3 題20%

📌 總分 ≥ 80 分才允許發布，目前平均品質分數為 97 分。

✅ 斷點續傳機制

系統透過 article-manifest.json 記錄每篇文章的狀態。若生成過程因 API 配額或網路問題中斷，重新執行腳本時會自動跳過已成功生成的檔案，直接續傳未完成的文章。

5.2 AI 協作流程標準

# AI 協作標準流程（適用於所有 LLM 代理） 1. 接收指令 → 解析任務類型 2. 檢查 .env 安全性（絕不讀取實際 Key） 3. 執行 PowerShell 腳本（僅限授權目錄） 4. 輸出日誌與結果（JSON 格式） 5. 回報戰情室（Gmail HTML 通知）

⚠️ 安全界線（重述）
  • ❌ 不可將 .env 上傳至 Git 或網頁
  • ❌ 不可暴露 API Key 於日誌或交接文件
  • ❌ 不可繞過系統安全或平台權限
  • ✅ 所有憑證僅儲存於本地 .env

憑證儲存位置存取權限備註

YOUTUBE_REFRESH_TOKEN.env僅限本地OAuth 2.0

6.2 Git 機密檔案攔截

# .gitignore 規範（確保以下檔案不上傳） .env client_secret.json *.wav logs/ ahpal-backup/ __pycache__/ *.pyc
🚨 禁止事項
  • ❌ 不得將任何憑證寫入程式碼或網頁
  • ❌ 不得在日誌中記錄 API Key 或密碼
  • ❌ 不得提交 .env 至 GitHub
  • ✅ 新進工程師需自行建立 .env

7. 部署與維運流程

7.1 標準部署流程

# 完整自動化部署（指令列） cd C:\Users\User\ahpal-static .\scripts\ahpal-master.ps1 → [1] # 或使用 CMS 面板一鍵部署（推薦） 開啟 https://www.ahpal.com/dashboard.html → 點擊「🚀 完整部署」

7.2 部署後驗證清單

  • ☐ 首頁可正常訪問（https://www.ahpal.com/）
  • ☐ 遊戲間可正常訪問（https://www.ahpal.com/game/）
  • ☐ 全部分類頁面可正常訪問（categories.html）
  • ☐ Sitemap 已更新（sitemap.xml）
  • ☐ Giscus 留言區正常載入
  • ☐ AdSense 廣告正常顯示
  • ☐ 部署報告郵件已收到

7.3 每日維運檢查

# 每日維運 SOP（建議 09:00 執行） # 1. 檢查網站狀態 Invoke-WebRequest -Uri https://www.ahpal.com -Method Head # 2. 檢查 Git 同步 git status git pull # 3. 檢查 API 配額 .\scripts\check-deepseek-balance.ps1 # 4. 檢查排程任務 Get-ScheduledTask | Where-Object { $_.TaskName -like "*AHPAL*" }
✅ 故障通報程序
  1. 發現異常 → 立即截圖記錄錯誤訊息
  2. 透過 Gmail 通知董事會執行長
  3. 執行 .\scripts\check-all.ps1 進行全面檢查
  4. 若無法立即修復，執行備份還原程序
  5. 記錄故障原因與修復方式至日誌
