❌ 錯誤 1：Add-Type System.Net.Mail 失敗

📌 錯誤訊息
Add-Type : 無法新增類型。找不到組件 'System.Net.Mail'。 位於 線路:1 字元:1 + Add-Type -AssemblyName System.Net.Mail + ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ + CategoryInfo : ObjectNotFound: (System.Net.Mail:String) [Add-Type], Exception + FullyQualifiedErrorId : ASSEMBLY_NOT_FOUND,Microsoft.PowerShell.Commands.AddTypeCommand
🔴 根因分析

PowerShell 5.1 及更早版本 中，System.Net.Mail 不是獨立的可載入組件，它包含在 System 組件中。

✅ 解決方法
# ❌ 錯誤寫法 Add-Type -AssemblyName System.Net.Mail # ✅ 正確寫法（適用於所有 PowerShell 版本） Add-Type -AssemblyName System # 或直接使用，無需 Add-Type $smtpClient = New-Object System.Net.Mail.SmtpClient
📌 教訓

不要假設所有 PowerShell 版本都支援獨立的 System.Net.Mail 組件。
永遠先測試，再部署。

❌ 錯誤 2：SMTP 郵件發送失敗

📌 錯誤訊息
Send-MailMessage : 無法驗證 'From' 參數上的引數。引數為 Null 或空的。 位於 線路:1 字元:50 + ... Send-MailMessage -To "praystone@gmail.com" -From $env:SMTP_USER ... + ~~~~~~~~~~~~~~ + CategoryInfo : InvalidData: (:) [Send-MailMessage]，ParameterBindingValidationException + FullyQualifiedErrorId : ParameterArgumentValidationError
🔴 根因分析

$env:SMTP_USER 為空，因為 尚未執行 ahpal-static.ps1 載入環境變數。
.env 檔案中的變數不會自動載入到 PowerShell 會話中。

✅ 解決方法
# 執行前必須先載入環境變數 .\scripts\ahpal-static.ps1 # 或手動載入 .env Get-Content .env | ForEach-Object { if ($_ -match '^([^=]+)=(.*)$') { [Environment]::SetEnvironmentVariable($matches[1], $matches[2]) } }
📌 教訓

永遠在執行任何腳本前先執行 ahpal-static.ps1。
環境變數不是自動載入的，這是 PowerShell 101，但最容易忘記。

❌ 錯誤 3：Emoji 顯示為亂碼

📌 錯誤現象
🎮 遊戲間 🎮 遊戲間
🔴 根因分析

auto-history-batch.ps1 中的「自動修復」區塊，將所有 Emoji 替換成了 🎮 格式。

# 罪魁禍首 $content = $content -replace '🎮', '[🎮]' # 變成 [🎮] # 但實際上變成了 🎮

更糟的是，這個修復被寫入 html_builder.py，導致所有新生成的頁面都包含被破壞的 Emoji。

✅ 解決方法
# 1. 從 Git 恢復 html_builder.py git checkout src/html_builder.py # 2. 批量修復所有文章的 Emoji $emojiMap = @{ '\[📖\]' = '📖' '\[📚\]' = '📚' '\[🎮\]' = '🎮' '\[💬\]' = '💬' # ... 更多映射 } # 替換所有文章中的被破壞 Emoji # 3. 重新生成頁面 python -c "from src.html_builder import create_default_index, generate_category_pages, generate_categories_page; create_default_index(); generate_category_pages(); generate_categories_page()" # 4. 部署 npx wrangler pages deploy . --project-name=ahpal-pages
📌 教訓

永遠不要自動修改核心檔案。
自動修復應該只針對輸出，不應該修改源代碼。
如果必須修改，請先備份並在修改後驗證。

🛑 永久修復

從 auto-history-batch.ps1 中 移除 整個「自動修復 html_builder.py」區塊。

❌ 錯誤 4：PowerShell JSON 寫入編碼混亂

📌 錯誤現象
# PowerShell 寫入的 JSON 中，中文字變成亂碼 "keyword": "隡??蝟餌絞撌亦?撣恬?DevOps 蝛輯??唬??詨?嚗?曄??撖行 Root 甈?撖Ⅳ嚗??舐撣賡妣摰?"
🔴 根因分析

PowerShell 在傳遞多行 JSON 給 WriteAllText 時，中文字元被錯誤編碼。
這是因為 PowerShell 的 @' ... '@ 字符串在傳遞時發生意外的編碼轉換。

✅ 解決方法
# ✅ 使用 Python 寫入 JSON python -c " import json pending = [ ... ] # 完整 JSON 資料 with open('data/pending-articles.json', 'w', encoding='utf-8') as f: json.dump(pending, f, ensure_ascii=False, indent=2) "
📌 教訓

處理中文 JSON 時，優先使用 Python 而非 PowerShell。
PowerShell 的字符串處理對 Unicode 和 Emoji 支援不夠穩定。
當資料量大或包含特殊字符時，Python 是更可靠的選擇。

❌ 錯誤 5：API 餘額耗盡

📌 錯誤現象
📊 目前餘額：¥0.00 CNY ❌ 餘額不足，無法繼續生成
🔴 根因分析
  • 一次生成了 57 篇文章（含 Responses API + Reasoning）
  • 單日消耗約 ¥3.43
  • 帳戶總餘額僅 ¥8.42（累計消費）
  • 沒有建立餘額告警機制
✅ 解決方法
# 1. 建立餘額監控 .\scripts\check-deepseek-balance.ps1 # 2. 設定餘額告警（在腳本中） if ($TotalBalance -lt 1.0) { Write-Host "⚠️ 餘額不足，停止生成" exit 1 } # 3. 只在空閒時段執行（18:00-09:00） # 4. 關閉 Reasoning 和 Search 以節省成本 # 5. 避免使用 Pro 模型
📌 教訓

永遠在批次生成前檢查餘額。
建立自動化餘額告警，在餘額低於閾值時停止生成。
高峰時段（09:00-18:00）價格是空閒時段的 2 倍，盡量避開。

❌ 錯誤 6：歷史腦洞文章在根目錄

📌 錯誤現象
# 文章在根目錄而非 history/ C:\Users\User\ahpal-static\qin-shi-huang-iphone-apps.html C:\Users\User\ahpal-static\butler-ming-eunuch-sop.html C:\Users\User\ahpal-static\programmer-qing-astronomy.html # ... 等 35+ 篇
🔴 根因分析

違反死命令 #3：文章必須放在對應分類目錄下。
歷史腦洞文章必須放在 history/ 目錄。

✅ 解決方法
# 移動所有歷史腦洞文章到 history/ Move-Item .\*.html .\history\ -Force # 檢查根目錄是否還有殘留 Get-ChildItem *.html | Where-Object { $_.Name -notin @('index.html','categories.html','404.html') } # 更新 master-articles.json 中的路徑 python -c " import json with open('data/master-articles.json', 'r', encoding='utf-8') as f: articles = json.load(f) for a in articles: if a.get('category') == '📜 歷史腦洞' and '/' not in a.get('filename', ''): a['filename'] = f'history/{a[\"filename\"]}' with open('data/master-articles.json', 'w', encoding='utf-8') as f: json.dump(articles, f, ensure_ascii=False, indent=2) "
📌 教訓

死命令不是裝飾品，要嚴格遵守。
新增文章時，filename 欄位必須包含目錄路徑。
建議在 add-articles.ps1 中自動檢查並強制分類目錄。

❌ 錯誤 7：文章檔名包含中文

📌 錯誤現象
history/Gemini 與 DeepSeek 的電子墓碑：當 AI 在產線上壯烈犧牲.html
🔴 根因分析

違反死命令 #2：文章檔名強制使用英文。

✅ 解決方法
# 重新命名為英文 Rename-Item "history/Gemini 與 DeepSeek 的電子墓碑：當 AI 在產線上壯烈犧牲.html" "gemini-deepseek-elegy.html" # 檢查所有中文檔名 Get-ChildItem -Recurse -Filter "*.html" | Where-Object { $_.Name -match '[\u4e00-\u9fa5]' }
📌 教訓

永遠使用英文檔名。
在 article_generator.py 中已經有強制轉換邏輯，但手動新增時仍需注意。
建議在 add-articles.ps1 中自動檢查並拒絕中文檔名。
