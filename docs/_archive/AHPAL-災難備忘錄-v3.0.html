❌ 錯誤 11：未掃描目錄直接新增 → 重複生成

📌 錯誤現象
# 情境：在已有 167 篇 life/ 文章的情況下 # 直接提供 100 篇新主題，未先掃描目錄 # 結果：第一次執行時，有 91 篇已存在，實際只生成 9 篇 # 第二次執行時，100 篇全部已存在 → 0 篇生成 [2026-08-17 02:39:24] 📄 已存在: 167 篇 [2026-08-17 02:39:25] ⚠️ 缺失 100 篇文章，開始生成... ← 這次是對的
🔴 根因分析
  • 沒有先執行 ls life/ 掃描現有檔案
  • 憑記憶/猜測提供主題，未與現有清單比對
  • 導致重複提供已存在的主題，浪費時間與 API 成本
✅ 解決方法：強制掃描 SOP
# ============================================================ # 🔍 新增文章前強制掃描 SOP # ============================================================ # 步驟 1：切換至目標目錄 cd C:\Users\User\ahpal-static\life # 步驟 2：掃描現有檔案清單 (輸出至文字檔) ls *.html | ForEach-Object { $_.Name } > existing-files.txt # 步驟 3：統計現有文章數量 (ls *.html).Count # 步驟 4：比對現有主題 (提取 keyword) # 從 master-articles.json 中提取所有 life/ 的 keyword python -c "import json; data=json.load(open('data/master-articles.json')); print('\n'.join([a['keyword'] for a in data if a.get('filename','').startswith('life/')]))" > existing-keywords.txt # 步驟 5：對比新清單，過濾掉已存在的 # 只有當 MissingArticles.Count > 0 時才執行生成
📌 教訓

永遠先掃描，永遠先比對。
每次新增文章前，必須先執行目錄掃描，確認實際缺失數量。
「我覺得有缺」不等於「真的有缺」。

🔍 新增文章強制掃描 SOP (v3.0 核心)

每次新增文章前，必須 執行以下流程，確保不重複、不浪費。

  1. 切換至專案目錄 cd C:\Users\User\ahpal-static
  2. 掃描目標目錄現有檔案 (以 life/ 為例) ls life/*.html | ForEach-Object { $_.Name }
  3. 統計現有文章數量 (ls life/*.html).Count
  4. 從 master-articles.json 提取現有主題 python -c "import json; data=json.load(open('data/master-articles.json')); print('\n'.join([a['keyword'] for a in data if a.get('filename','').startswith('life/')]))"
  5. 比對新清單，過濾已存在主題 (使用 Python) # 在 pending-articles.json 寫入前，先比對 master-articles.json
  6. 確認缺失數量 > 0 後才執行生成 if ($MissingArticles.Count -gt 0) { python src/main.py --force deepseek }
  7. 記錄掃描結果至日誌 # 已內建於 auto-life-batch.ps1 步驟 3
✅ 自動化掃描已整合

auto-life-batch.ps1 已在步驟 3 自動執行掃描與比對，
日誌中會顯示 📄 已存在: X 篇 與 ⚠️ 缺失 X 篇文章。
執行前請務必確認日誌輸出。

🔋 無人值守終極解決方案 — SYSTEM 帳戶排程

完全繞過 PIN 碼，實現真正的無人值守。

❌ 互動式任務 (Interactive)
  • 使用您的帳戶
  • LogonType: Interactive
  • ⚠️ 需要 PIN 碼
  • 視窗可見 (Normal)
  • 適合手動測試
✅ SYSTEM 任務 (ServiceAccount)
  • 使用 SYSTEM 帳戶
  • LogonType: ServiceAccount
  • ✅ 無需 PIN 碼
  • 視窗隱藏 (Hidden)
  • ✅ 適合正式排程

🔧 建立 SYSTEM 帳戶無人值守排程

# ============================================================ # 🚀 建立 SYSTEM 帳戶無人值守排程 (5分鐘後執行) # ============================================================ # 1. 停用互動式任務 (避免衝突) Disable-ScheduledTask -TaskName "AHPAL_LifeBatch" -ErrorAction SilentlyContinue # 2. 計算執行時間 $RunTime = (Get-Date).AddMinutes(5) # 3. 建立 SYSTEM 帳戶背景任務 $Action = New-ScheduledTaskAction -Execute "powershell.exe" -Argument "-ExecutionPolicy Bypass -File `"C:\Users\User\ahpal-static\scripts\auto-life-batch.ps1`" -WindowStyle Hidden" $Trigger = New-ScheduledTaskTrigger -Once -At $RunTime $Settings = New-ScheduledTaskSettingsSet ` -AllowStartIfOnBatteries ` -DontStopIfGoingOnBatteries ` -WakeToRun ` -StartWhenAvailable ` -RunOnlyIfNetworkAvailable # ⭐ 關鍵：使用 SYSTEM 帳戶 $Principal = New-ScheduledTaskPrincipal -UserId "SYSTEM" -LogonType ServiceAccount -RunLevel Highest # 4. 註冊新任務 Register-ScheduledTask -TaskName "AHPAL_LifeBatch_System" -Action $Action -Trigger $Trigger -Settings $Settings -Principal $Principal -Force Write-Host "✅ 無人值守排程已建立 (SYSTEM 帳戶)" -ForegroundColor Green Write-Host "📌 任務將於 $($RunTime.ToString('yyyy-MM-dd HH:mm:ss')) 執行" -ForegroundColor Yellow Write-Host "🔑 無需輸入 PIN 碼" -ForegroundColor Cyan
📌 使用時機
  • 手動測試 / 監控 → 使用 Interactive 模式 (需輸入 PIN)
  • 正式無人值守排程 → 使用 SYSTEM 帳戶 模式
  • 混合方案 → 同時保留兩個任務，平時停用 Interactive

❌ 錯誤 9：服務條款誤設 NOINDEX

<meta name="robots" content="noindex, follow">

服務條款、隱私權政策、關於我們等頁面被錯誤地設為 noindex，導致搜尋引擎無法索引，影響網站信任度與完整性。
